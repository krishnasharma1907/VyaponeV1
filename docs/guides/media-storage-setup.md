# VyapOne — Media Storage Architecture & Setup Guide [VO-032]

## Overview
VyapOne implements a secure, direct-to-storage media pipeline with strict tenant isolation, server-governed authorization, byte-level magic byte verification, and safe two-phase deletion.

---

## 1. Bucket Architecture

VyapOne partitions storage objects into two distinct buckets:

| Bucket Name | Public Access | File Size Limit | Permitted Categories | Description |
|---|---|---|---|---|
| `vyapone-public-media` | **Public** (Direct CDN Read) | 5 MB | `business_logo`, `catalogue_image`, `website_asset` | Public branding, catalogue items, and approved website assets. |
| `vyapone-private-media` | **Private** (Signed URLs only) | 10 MB | `document_attachment`, `onboarding_upload` | Invoices, PAN cards, statutory records, raw onboarding photos. |

### Critical Invariant: Bucket & Database Visibility Alignment
To prevent accidental public exposure of private assets, PostgreSQL enforces the constraint:
```sql
CONSTRAINT chk_media_items_bucket_visibility CHECK (
    (bucket = 'vyapone-public-media' AND is_public = true) OR
    (bucket = 'vyapone-private-media' AND is_public = false)
);
```

---

## 2. PostgreSQL Privilege Separation

### Table: `public.media_items`
- **`anon`**: `GRANT SELECT` (restricted by RLS to `is_public = true AND status = 'ready'`).
- **`authenticated`**: `GRANT SELECT` only (restricted by RLS to caller's business / workspace).
- **Direct writes (`INSERT`, `UPDATE`, `DELETE`)**: **REVOKED from `authenticated` and `anon`**.
- **Mutations**: Performed exclusively by trusted server-side procedures (`MediaService`) via administrative `service_role` credentials.

This model completely prevents malicious or compromised authenticated clients from tampering with:
- `bucket` or `object_key` (preventing unauthorized storage key reassignment)
- `status` (preventing bypass of byte-level verification)
- `is_public` (preventing premature exposure of private assets)
- `verified_at`, `file_size_bytes`, `detected_content_type`

---

## 3. Storage Object Key Naming Convention

All object keys are generated server-side using unpredictable, tenant-isolated paths:
```text
tenants/{business_id}/{category}/{media_id}.{extension}
```
- `business_id`: UUID of sovereign business owner.
- `category`: Validated media category.
- `media_id`: Unpredictable UUID generated by server.
- `extension`: Canonical extension derived from detected MIME type.

---

## 4. Two-Phase Safe Deletion & Reconciliation

Because cloud object storage and PostgreSQL do not participate in a single distributed transaction, VyapOne implements a two-phase deletion protocol:
1. **Mark `deletion_pending`**: Metadata status set to `deletion_pending` in `public.media_items`.
2. **Storage Removal**: Cloud storage object deleted via `IStorageProvider.deleteObject()`.
3. **Mark `archived`**: Metadata status transitioned to `archived`.
4. **Failure Recovery**: If storage removal fails, the item remains in `deletion_pending` and records an audit event (`media.deletion_failed`).
5. **Reconciliation**: Background workers or administrative actions call `retryPendingDeletion(mediaId, businessId)` to drain pending deletions.

### Business Deletion Safeguard
Foreign key `public.media_items.business_id` is set to `ON DELETE RESTRICT` rather than `CASCADE`. This guarantees that deleting a business record cannot silently orphan active storage objects in the cloud. All media items must be archived/cleaned up before business removal.

## 5. Development & Local Supabase Setup

When testing with live local Supabase Storage (`supabase start`):

1. **Create Buckets via Supabase Storage API or SQL Seed**:
```sql
-- Local development storage bucket provisioning
INSERT INTO storage.buckets (id, name, public, file_size_limit, allowed_mime_types)
VALUES
  ('vyapone-public-media', 'vyapone-public-media', true, 5242880, ARRAY['image/png', 'image/jpeg', 'image/webp', 'image/svg+xml']),
  ('vyapone-private-media', 'vyapone-private-media', false, 10485760, ARRAY['image/png', 'image/jpeg', 'image/webp', 'application/pdf', 'text/csv', 'application/vnd.openxmlformats-officedocument.spreadsheetml.sheet'])
ON CONFLICT (id) DO NOTHING;
```

2. **Storage Policies (`storage.objects`)**:
- Direct uploads are authorized via presigned upload URLs generated by `service_role`.
- Public reads on `vyapone-public-media` are permitted for all GET requests.
- Private reads on `vyapone-private-media` require presigned URLs generated by `MediaService.getMediaUrl()`.
